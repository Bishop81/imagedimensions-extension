--- NAME -------------------------------------------------------------
ImageDimensions - Image Size Auditor

(Edge reads the name from the manifest, so this should already be filled in. If it shows
an em dash rather than the hyphen above, that is correct and comes from the manifest.)


--- SHORT DESCRIPTION -------------------------------------------------
See every image's real size versus the size it's displayed at - on any page, including localhost and pages behind a login.


--- DESCRIPTION -------------------------------------------------------
Every image on a page has two sizes: the pixels in the file, and the pixels the browser actually draws. When the first is much larger than the second, the visitor downloads weight they never see — and it is invisible until you go looking.

ImageDimensions shows you both numbers for every image on the page you are on, sorted worst first.

WHAT YOU GET

• Every image measured — the file's real pixel size next to the size it was drawn at
• A multiplier showing how much was wasted, so a 3000×2000 file in a 250×167 slot reads plainly as 144×
• CSS background images included — roughly a fifth of the images on a typical page, and most audits skip them entirely
• Click any row to scroll straight to that image and highlight it on the page

WHY NOT JUST USE A WEBSITE SCANNER

Hosted scanners load your page in a headless browser somewhere else. That means they cannot see anything behind a login, anything protected by a bot filter, or anything running on localhost or a staging domain — which is exactly where you are working when the problem is still cheap to fix.

This runs in your browser, on the page in front of you.

IT MEASURES AGAINST YOUR ACTUAL DISPLAY

A 400×400 image in a 200×200 slot is wasteful on a standard display and exactly right on a retina one. A headless scanner cannot tell the difference, because it does not have a screen. This extension knows your real device pixel ratio, so it will not flag a correctly-served retina image — and it will flag one that is oversized even after retina is accounted for.

PRIVACY

No account. No network requests. No analytics. No storage. Nothing about the pages you visit leaves your machine, because nothing is ever sent anywhere.

It asks for two permissions and no more: permission to read the current tab when you click the icon, and permission to run the measurement on that click. There are no host permissions, so it has no standing access to any site.

The source is public: github.com/Bishop81/imagedimensions-extension

FROM THE MAKERS OF IMAGEDIMENSIONS.COM

The same measurement is available as a hosted scanner, an MCP server for AI coding agents, and a CLI with a GitHub Action for failing a build on oversized images. See imagedimensions.com

--- PRIVACY FORM (the tab that gets submissions rejected) --------------
Every answer below is literally true of the code, which is what makes it safe to say.
These are the answers Chrome approved, with the browser name made neutral.


SINGLE PURPOSE DESCRIPTION (max 1000)

This extension audits the images on the web page the user is currently viewing. For each image it reports the file's intrinsic pixel dimensions alongside the dimensions the browser rendered it at, and flags images whose file is substantially larger than the space it is displayed in. Clicking a result scrolls that image into view and highlights it.


ACTIVETAB JUSTIFICATION (max 1000)

Used to read the images of the page the user is currently viewing. Access is granted by the browser only for the tab the user is on, and only when the user clicks the extension's toolbar icon. The extension requests no host permissions, so it has no access to any site unless the user explicitly invokes it on that tab.


SCRIPTING JUSTIFICATION (max 1000)

Used to run the measurement function in the active tab when the user clicks the toolbar icon. The injected function reads each image's naturalWidth and naturalHeight and its rendered bounding box, plus the element's computed background-image, and returns those measurements to the popup. A second function is injected only when the user clicks a result: it scrolls that element into view and draws a temporary highlight, which it then removes. Neither function modifies the page's content.


ARE YOU USING REMOTE CODE?   ->   No

Justification (max 1000)

All executable code ships inside the extension package. There are no script tags or module imports pointing at external files, no eval or new Function, no WebAssembly, and no network requests of any kind at runtime. The popup measures the active tab locally and renders the result.


WHAT USER DATA DO YOU PLAN TO COLLECT?   ->   tick NOTHING

None of the categories apply. The extension transmits nothing, stores nothing and has no
analytics.

On "website content", which is the one a reviewer may query: the extension READS image
dimensions from the page in order to display them, but does not COLLECT them - nothing is
transmitted, persisted or retained once the popup closes. The disclosure asks about
collection. The public source backs that up.

    store/promo-440x280.png

Large promotional tile, optional, 1400x560:
    store/edge-hero-1400x560.png

WARNING: the Edge logo and the Chrome store icon are different files on purpose. Chrome's
store icon carries 16px of transparent padding inside a 128px canvas because the Chrome
Store draws its own frame around it. Edge's logo is full bleed. Swapping them gets a
double frame on one store and a floating mark on the other.

Both Edge-only assets are generated, not hand drawn. One command makes them:

    ./scripts/make-edge-assets.sh

It rasterises the site's favicon.svg - the same geometry the toolbar icons were drawn
from - at 300px for the logo and asserts the output size, then renders the hero tile.
Re-run it if the mark ever changes. Never rescale a PNG by hand.

The hero tile shows what the popup itself shows: a row per image, the file's own size
next to the size it was drawn at, and the overshoot as a multiple. Every multiplier on it
is COMPUTED from the two sizes beside it at render time, never typed - 3000x2000 drawn at
250x167 is 143.7, which prints as 144x. Change a row's numbers and the badge follows.

One thing worth deciding for yourself: the mark's height-ruler ticks sit just outside the
blue square, on transparency, so on a white store card they read as faint marks at the
right edge. That is exactly how the icon looks in the browser toolbar today and on the
live Chrome listing, so it ships consistent. Changing it is a redesign of the mark, not a
store-asset fix.


=====================================================================
CREDENTIALS
=====================================================================

extension/.env carries EDGE_CLIENT_ID and EDGE_STORE_KEY, copied from the DomainIntel
extension, which publishes to Edge today. Probed on 2026-09-26 against the Edge API: both
a known product and a nonexistent one answer 404, not 401, so the key pair authenticates
at account level.

What that does not prove is authorisation for a NEW product, because an unauthorised
product and a missing one look identical from outside. Once the product exists, one
--check call against its real id settles it. If that returns 401, generate a fresh pair in
Partner Center under the Edge program's Publish API section - but check first whether
issuing new credentials invalidates DomainIntel's, the way Mozilla's API keys do.
